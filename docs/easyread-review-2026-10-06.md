# EasyRead 1.2.5 对 YiRead 的借鉴价值

审阅日期：2026-10-06。对象：本机 `D:\easyread-1.2.5` 源码。此次是静态源码对照，没有启动 EasyRead、安装依赖或调用其翻译引擎。README 中的宣传性速度、价格和效果未作为验证结论。

## 结论

两个项目都采用 Python 本地服务、原生 HTML/CSS/JS 和 JSON 文件存储，许多交互机制适合移植。优先借鉴翻译调度、草稿保护与阅读导航，而不是照搬整体界面、数据结构和 AI 聊天模块。YiRead 保留现有学术风格、稳定原文编号及原文/译文/任务分离。当前逐句翻译默认关闭，保留用户手动开启和「逐句对齐重译」。

## 第一优先级：翻译效率与可恢复性

### 1. 把请求粒度与定位粒度分开

EasyRead `easyread/config.py` 默认每批两页、并发一批；`easyread/translate.py:translate_pages` 支持可配置分批及受限并发（代码上限8）。YiRead 当前文献串行，段落或句子逐次请求；大文本按5000字符切分，逐句模式每句独立请求。

建议 YiRead 按字符和预估 token 预算合并几个段落，一次提交携带稳定编号的 JSON 列表，要求逐项返回译文。逐句模式也可以多句一起请求、每句独立返回，保存原来的句子坐标。**逐句对齐不必等于每句一次网络请求。** 默认继续按段翻译；批量能力是调度优化，不改变用户的模式选择。

首版并发1，允许选择2；遇到429自动减速，结合服务商能力调整。不要直接把并发设成8，不承诺固定倍数提速。返回必须核对编号集合、重复编号、缺项及截断；缺失项单独重试，已经成功的项立即保存。

EasyRead 允许模型生成块结构并规范化编号；YiRead 不应照搬这点，必须保留本地提取的稳定原文编号，避免已有笔记和跟随锚点失效。

验收：同一模拟延迟服务下比较请求数、首段可读时间和总耗时；批次少一项不得错配后续译文；开启逐句模式后坐标不变。

### 2. 自动重试、失败列表与部分完成

EasyRead `easyread/openai_api.py:complete` 对429和部分5xx进行重试，使用 Retry-After 或指数等待；`translate_pages` 最终收集失败页，其他批次可以继续。`easyread/jobs.py` 展示部分完成状态。YiRead 的 worker 外层异常会让当前文献任务停止，已完成段落可以续传，但当前没有独立失败项列表、自动退避或取消入口。

建议增加：临时故障有限重试、失败段落/页清单、「仅重试失败部分」、取消或暂停后保留结果。401、无效模型和余额不足及时停止；429区分临时限流与额度耗尽。超时重试可能再次计费，不能当成免费重复调用；并发和重试应共用预算，避免重试层层叠加。

验收：中间一段持续失败时，后续可用段落仍完成；补译只请求失败部分；取消后不再派发新请求，已有结果可读。

### 3. 翻译范围与用量反馈

EasyRead `scope_pages` 支持全文、正文、页码区间；`usage.py` 记录 token。建议 YiRead 提供「全文 / 当前页 / 指定页码」，随后再做可核对的正文范围识别。参考文献起始页可能同时包含结论，不能直接整页丢弃；识别到疑似参考文献时让用户确认范围。

任务显示完成段数/总段数、当前页、失败原因、实际 token 用量（接口返回时）。费用估算只在有明确单价及缓存 token 口径时显示，并说明是估算；不要用固定“每篇多少钱”。

## 第二优先级：保存可靠性与操作便利

### 4. 草稿自动保存与待同步队列

EasyRead `web/js/reader/store.js` 将操作先写 localStorage outbox，再发送本地服务，确认成功才移除；失败后退避补发，UI 明确显示暂存状态。`docs/design.md` 还说明编辑草稿定期保存。YiRead 已有服务器持久化、原子写入和笔记版本冲突保护，保存失败时保留当前输入，但编辑中的草稿并非独立持久化记录。

建议先做小改动：笔记与人工修订输入延迟自动存为草稿，再显示「草稿已暂存 / 保存中 / 已保存 / 保存失败」。第二步才做幂等操作队列。保留 YiRead 的版本冲突保护，冲突需要核对；不能简单用客户端时间戳判定谁覆盖谁，也不能后台重试后静默覆盖其他窗口的修改。

验收：输入未保存时刷新仍可恢复；服务离线时草稿仍在；恢复服务不会产生重复笔记；冲突不吞用户输入。

### 5. 原文反向定位、返回阅读位置与少量快捷键

EasyRead `web/js/reader/pageview.js:blockAt` 从归一化原页坐标寻找点击块，再跳转译文；`jumpback.js` 保存跳转前的位置并提供返回按钮；`keys.js` 提供阅读操作。

建议 YiRead 增加点击原 PDF 文字区域定位译文、从笔记/页码跳转后「返回刚才的位置」、上一段/下一段、记笔记、Esc关闭等少量快捷键。沿用现有行矩形，优先匹配已可靠定位的句子或段落。跳转后短暂抑制自动跟随，避免滚动事件立即抢回刚点击的位置。输入框和编辑器内不得触发阅读快捷键。

此项直接服务实验人员核对反应条件、收率和表格，不依赖额外模型调用。

## 第三优先级：文献管理与长文性能

### 6. 可恢复删除与选中文字批注

EasyRead `trash.py` 将文献目录移动到回收站；YiRead 当前删除原文、译文和任务后没有产品内恢复方式。适合新增可恢复删除，但 YiRead 数据分散在 library/translation/jobs，需一个清单记录关联文件及恢复状态，不能只移动 library 文件夹。注意中途失败回滚和同编号冲突。

EasyRead `anchor.js` 用 quote/prefix/suffix 定位选中文字。YiRead 现有段落笔记可继续保留，再补充选中文字写笔记和高亮。译文修改后无法准确找到原句时，标注「位置待核对」，保留笔记，不能猜测定位到重复句。

### 7. 图表保真与加载性能

EasyRead 把页面图和文字定位产物保存磁盘，还能裁切图、渲染 TeX，并检查公式格式。YiRead 页面 PNG 和布局使用有界内存缓存，长文再次翻阅会重新渲染部分页面；DOM 则一次建立全文。

建议先加入带源文件版本和渲染参数的磁盘缩略图/页面缓存、邻近页面预加载、远页延迟加载。确认大文献性能瓶颈后再做 DOM 虚拟化，避免改变高度造成句子跟随和书签跳转漂移。

合成文献更应保留原始反应式和结构图，可提供与当前译文对应的图表预览/局部放大。不要让模型重画化学结构来代替原图。KaTeX 对数学公式有价值，但不能自动恢复 PDF 中已经丢失的结构式、上下标或立体化学；数字、单位、化合物编号可以加核对提示，不能自动改正。

## 本机登录翻译引擎：有可参考实现，但需单独评估

EasyRead `easyread/engines.py:run_codex` 查找本机 codex 可执行文件，用 `codex exec` 子进程、read-only sandbox、ephemeral 会话、JSON事件和临时输出文件取得结果，并支持附加原页图片。

这证明该源码实现的是**调用已安装并登录的 Codex CLI**，不是控制 ChatGPT 桌面窗口，也不是将 ChatGPT 登录凭据转成普通 API Key。是否能在本机成功运行、当前账号权限、可选模型和用量需要后续单独验证，不能据 README 宣称无限免费。

如果后续引入，建议作为可选引擎，与现有 API 引擎并存；检测安装与登录状态、明确用量来源、有超时和取消机制、限制允许参数、在隔离的临时文献目录执行。不要复制 arbitrary extra_args 作为普通用户设置，也不要读取浏览器 cookies。

## 不建议当前照搬

- 复杂 AI 多会话聊天和全文问答：会扩大界面与成本，当前优先保持翻译阅读专注。
- 模型生成整套块编号与结构：易影响 YiRead 已有锚点和笔记。
- 自动把术语全文替换：科研术语需要上下文，可做预览确认后替换。
- 原页深色反相：保持 YiRead 的 PDF 白纸底色和橙色跟随，化学结构与彩色图保持原样。
- 离线分享 HTML：用户先前明确暂缓分享，继续暂缓。
- 默认高并发与每次改版重译旧文献：不符合费用控制和资料稳定性。

## 建议实施顺序

1. 翻译自动退避、失败项单独重试、范围选择和明确进度。
2. 保留编号的批量请求，实测后开放低并发；显示实际 token。
3. 笔记/修订草稿自动保存，随后完善待同步队列。
4. 点击原文定位译文、跳转返回及基础快捷键。
5. 回收站、文字级批注、原图局部放大及长文缓存。
